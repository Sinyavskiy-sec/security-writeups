# SQL Injection: обход фильтра категории через WHERE clause (PortSwigger Web Security Academy)

**Категория:** SQL Injection
**Сложность лабы:** Apprentice
**Платформа:** PortSwigger Web Security Academy
**Тип уязвимости:** SQL Injection, retrieval of hidden data
**Инструменты:** Burp Suite (Proxy, Repeater)

---

## Цель

Приложение — интернет-магазин с категориями товаров. Часть товаров скрыта от обычных пользователей (не выпущены в продажу). Задача — используя SQL-инъекцию в параметре фильтрации по категории, обойти логику `WHERE` и получить в ответе сервера товары, которые не должны быть видны.

## Описание уязвимости

Приложение формирует SQL-запрос на бэкенде примерно так:

```sql
SELECT * FROM products WHERE category = 'Gifts' AND released = 1
```

Значение категории берётся из параметра запроса без должной валидации и подставляется напрямую в запрос. Это позволяет модифицировать логику `WHERE`-условия и полностью убрать фильтр `released = 1`, добавив всегда истинное условие через `OR`.

## Методология

### 1. Recon

Открыл каталог товаров, выбрал произвольную категорию (например, "Gifts") и через Burp Suite Proxy перехватил GET-запрос, отвечающий за фильтрацию:

```
GET /filter?category=Gifts HTTP/1.1
Host: <lab-id>.web-security-academy.net
```

### 2. Проверка инъекции

Отправил запрос в Burp Repeater. Изменил значение параметра `category`, замкнув исходную строковую константу и добавив условие, которое всегда истинно:

```
category=Gifts'+OR+1=1--
```

Логика итогового запроса на бэкенде превращается в:

```sql
SELECT * FROM products WHERE category = 'Gifts' OR 1=1--' AND released = 1
```

`--` комментирует остаток исходного запроса (в т.ч. `AND released = 1`), поэтому условие `released = 1` перестаёт применяться, а `1=1` истинно для каждой строки таблицы.

### 3. Отправка и проверка результата

Отправил модифицированный запрос через Repeater. В ответе сервера (HTTP 200) в теле страницы появились дополнительные товары, отсутствовавшие в исходном списке, — в том числе непубликуемые (unreleased) позиции.

## Payload

```
Gifts'+OR+1=1--
```

## Результат

Лаба пройдена — получен доступ к скрытым (unreleased) товарам, которые не должны отображаться обычным пользователям каталога.

## Impact (потенциальное влияние в реальном приложении)

- Раскрытие данных, не предназначенных для публичного доступа (в данном случае — товары; в реальных системах это могут быть чужие заказы, персональные данные, черновики контента и т.д.)
- Обход бизнес-логики приложения (фильтрация по `released`)
- При отсутствии дополнительных ограничений — потенциальная точка для расширения атаки: UNION-based извлечение данных из других таблиц, включая учётные записи пользователей

## Root cause

Пользовательский ввод конкатенируется в SQL-запрос напрямую, без использования параметризованных запросов (prepared statements) и без экранирования спецсимволов.

## Remediation

- Использовать параметризованные запросы (prepared statements) вместо конкатенации строк
- Валидировать/ограничивать допустимые значения параметра `category` через allowlist (раз число категорий конечно и известно заранее)
- Принцип наименьших привилегий для учётной записи БД, используемой приложением
- WAF как дополнительный (но не основной) слой защиты
